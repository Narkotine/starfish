# 2026-10-30 — session 58 : le bureau dessiné redevient le produit (ADR-21, lot 1)

**Demande** : une icône glissée dans une zone **quitte le bureau** sans que le fichier bouge, et tout revient si StarFish s'arrête. Après le mini-rapport, il choisit « StarFish dessine tout le bureau », clic droit proche de Windows 11 et modifiable, sans injection dans Explorer. Plan en 4 lots (T-089..T-092) ; ce commit livre le lot 1.

**Diagnostic de l'ancien mode** (ce qui l'avait fait retirer, ADR-20) : surface per-pixel **invisible** sur un enfant de Progman (ADR-15), menu de fond reconstruit sans sous-menus, icônes sans clic. Rien d'inhérent au mode.

**Fait** : `desktop_shell_view` (la vue `IFolderView2` du bureau, cross-process par les proxies système) ; fond **opaque** = fond d'écran capturé (`PrintWindow` sur la DefView, liste masquée) + icônes aux positions du shell + sélection ; vrais menus de fond et d'élément (sous-menus remplis par `WM_INITMENUPOPUP` seulement — T-071) ; double-clic = verbe par défaut de l'élément ; flèche de raccourci ; `--native-desktop` ; sonde `--drawn-desktop-probe`.

**Pièges** : `GetMenuState` lu comme séparateur sur une entrée à sous-menu (« Affichage » avalé) ; `CMF_CANRENAME` via proxy = `E_INVALIDARG` + menu rempli ; overlay à prendre dans la petite liste.

**Vérifié** : `ctest` 16/16, `--drawn-desktop-probe` 17/17 (dont : icône rangée ⇒ elle quitte le bureau, le fichier reste), `--crash-demo` / `--backdrop-demo` / `--product-probe` verts. `--icons-demo` : 1 échec (clic synthétique `SendInput` sur une icône native — mode `--native-desktop`, non touché ; probablement une fenêtre de l'utilisateur au-dessus du point). Captures : `build/captures/lot1_*.png`. Bureau natif rendu après chaque essai (marqueur absent).

## Lot 2 (T-090) : la synchronisation

**Fait** : `DesktopSurface` dit enfin qu'il a perdu sa fenêtre quand le bureau la détruit (`WM_DESTROY` non demandé → `desktopLost`, en différé ; avant, le chien de garde s'arrêtait **en silence** et rien n'était ré-hébergé après un redémarrage d'Explorer). Le produit lâche alors le bureau dessiné (icônes natives visibles) et le reprend quand le bureau est revenu (2 ticks de 2 s stables, 1 min max) ; les zones perdues sont ré-hébergées (1 s, 1 min max). Une liste que le shell ré-affiche est re-masquée (marqueur d'abord). La vue du shell se reconnecte si la DefView a changé. Écrans : `geometryChanged`/`logicalDotsPerInchChanged` suivis, fond recapturé si sa taille ne colle plus.

**Vérifié** : `ctest` 16/16 ; `--drawn-desktop-probe` **23/23** — redémarrage **simulé dans le processus** (nos fenêtres détruites, liste montrée comme le ferait un nouvel Explorer ; rien n'est envoyé à Explorer) : bureau lâché puis redessiné, zone ré-hébergée ; liste re-masquée ; nouvel élément dans une case libre. `--crash-demo` / `--backdrop-demo` / `--product-probe` verts. **Reste humain** : deux écrans / DPI mixte ; un vrai redémarrage d'Explorer.

## Lot 4 (T-092) : le menu clic droit façon Windows 11

**Fait** : `DesktopShellView::open*MenuModel` lit le **vrai** menu (fond ou sélection) en données, sous-menus remplis (`WM_INITMENUPOPUP`, T-071), l'`IContextMenu` gardé vivant jusqu'au choix (`invokeMenuCommand`). `core/context_menu` : clés stables par libellé (fr/en), profil Windows 11 (groupes, barre d'icônes Couper / Copier / Renommer / Partager / Supprimer, Coller sur le fond s'il y a quoi coller), le reste sous « Afficher plus d'options » (toujours dernier → le menu classique). `ui/modern_menu` : QMenu au style Win11 (coins DWM, Segoe UI, glyphes Segoe Fluent Icons, thème clair/sombre des applis). Config `%LOCALAPPDATA%\StarFish\context-menu.json` : `modern`, et par menu (`background`, `items`) `hidden`, `shown`, `order`, `custom` (programme + `%paths%`/`%path%`/`%desktop%`) ; les clés vues sont écrites dans `context-menu-keys.txt` ; tray « Personnaliser le menu clic droit... ». Windows 10, `"modern": false` et Maj+clic droit / Maj+F10 = menu classique natif.

**Pièges** : à travers le proxy, `GetCommandString` refuse un `pReserved` nul (`0x800706F4`) **et** rend le verbe coupé à sa 1ʳᵉ lettre (« r » pour refresh) → les verbes n'avaient **jamais** marché en cross-process (le renommage après « Nouveau » armé par verbe ne se déclenchait pas : corrigé, `N`/`.`). D'où des clés par libellé. Apostrophe typographique dans « chemin d’accès ». `initializer_list` dans une table statique = pointeur pendant (plantage, bureau réparé aussitôt par le marqueur T-046).

**Vérifié** : `ctest` **17/17** (nouveau `core_context_menu`) ; `--drawn-desktop-probe` **46/46** sans clic : menus composés, rendus et capturés, « Actualiser » exécuté par le menu, l'entrée StarFish revient à StarFish, bouton Renommer → notre édition, config (masquer / réordonner / ajouter) puis rendue telle quelle, « Afficher plus d'options » ouvre le classique. `--context-menu-probe` : dump des menus réels (diagnostic). Captures `build/captures/lot4_*.png`, `lot1_background_menu.png` (le vrai chemin produit).

**Décisions prises seul** : clés par libellé (seule source fiable) ; une extension inconnue reste sous « Afficher plus d'options » (comme Windows 11), ramenable par `shown` ; « Afficher plus d'options » non masquable ; config en JSON éditée à la main (pas d'éditeur graphique pour l'instant).

**Reste** : entrées `IExplorerCommand` des apps empaquetées (« Ouvrir dans le Terminal », Notepad...) non lues ; essai humain à la vraie souris / au clavier.
