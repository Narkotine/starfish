## 2026-10-13 — Session 4 : z-order, fenêtre Win32 pure, capture

**Objectif** : prouver objectivement que nos fenêtres se placent sous la couche d'icônes, et obtenir une preuve visuelle (l'utilisateur n'était pas devant l'écran aux runs précédents).

**Fait**
- Run Tk (échec) : la fenêtre Tk `overrideredirect` reste **au-dessus** de la DefView malgré `SetParent`/`SetWindowPos` — Tk restack ses fenêtres en interne. Vérification par la **chaîne de z-order des enfants de Progman** (`EnumChildWindows`) : notre fenêtre en index [0], DefView en [2] → au-dessus (mauvais).
- Correction d'interprétation au passage : `GW_HWNDPREV == 0` signifie **au-dessus** (pas en dessous) ; `WindowFromPoint` est inutilisable (répond `Shell_LightDismissOverlay` partout).
- Spike réécrit en **Win32 pur via ctypes** (fenêtre enregistrée + wndproc, sans Tkinter) = séquence de référence pour le portage Qt. Point critique : **effacer `WS_EX_TOPMOST`** avant insertion.
- Run Win32 (succès, ×2) : chaîne enfants = `DefView[0] / SysListView32[1] / SysHeader32[2] / notre fenêtre[3] / WorkerW[4]` → verdict **BELOW icon layer**. Fenêtre orange 500×260 visible 3-6 s au centre, capture d'écran intégrée (`experiments/out/spike_check.png`).
- Bug corrigé : le timer de capture se répétait (KillTimer ajouté).
- **Preuve visuelle** : la capture montre la fenêtre orange au-dessus du papier peint et **sous les fences de Fences**, qui la recouvrent partiellement → placement conforme au comportement de Fences (les zones vivent sous la couche d'icônes).

**Décisions / doc**
- ADR-4 complété : séquence Win32 de référence (SetParent Progman → style WS_CHILD sans WS_POPUP → clear WS_EX_TOPMOST → SetWindowPos sous DefView), vérification par chaîne de z-order.
- T-003 marqué ✅ (faisabilité prouvée) ; nouvelle tâche **T-016** : portage C++/Qt (`DesktopHost`).

**Prochaines actions** : T-016 (portage Qt du DesktopHost), T-004 (lecture Bureau + icônes shell), déblocage toolchain local.
