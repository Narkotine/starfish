## 2026-10-14 — Session 12 : T-006 pièce 3 — DnD `CF_HDROP` depuis l'Explorer

**Objectif** : accepter le drop de fichiers/dossiers depuis l'Explorer Windows vers une zone (T-006-3), en réutilisant la résolution d'items du scan bureau. La session a été interrompue une fois par la limite de fréquence (429) puis reprise.

**Fait**
- **Deux chemins, parce que la zone vit à deux endroits** :
  1. **Fenêtre Qt réelle** — `FenceView::setAcceptDrops(true)` + `dragEnterEvent`/`dragMoveEvent`/`dropEvent`. Qt expose le `CF_HDROP` de l'Explorer comme une liste d'URLs `file://` (`mimeData()->hasUrls()`). Chaque chemin local est résolu par `DesktopScanner::itemForPath()`, puis `addDroppedItems()`.
  2. **Surface hébergée** — Qt ne tourne jamais (la zone est une image hors écran, seul le HWND Win32 est à l'écran) : `DesktopSurface` enregistre un `IDropTarget` OLE (`ShellDropTarget`) sur son propre HWND. `CF_HDROP` → `DragQueryFileW` → handler `(point client, chemins)`. `OleInitialize` dans `attach()` (équilibré par `OleUninitialize` dans `detach()`), `RegisterDragDrop`/`RevokeDragDrop`, `setDropHandler`. `main.cpp` câble le handler à `fence->addDroppedItems`.
- **`ShellDropTarget`** (`src/platform/win/shell_drop_target.{hpp,cpp}`) : `IDropTarget` COM, comptage de références `InterlockedIncrement/Decrement`, `QueryGetData`/`GetData(CF_HDROP)` + `DragQueryFileW`. Le point de drop arrive en coordonnées écran → converti en coordonnées client via `GetWindowRect`.
- **`IconGrid::appendItems()`** : dédoublonnage par chemin, skip des items sans chemin, re-tri selon l'ordre courant, sélection vidée (un drop est un lot neuf). Retourne le nombre d'items ajoutés.
- **`DesktopScanner::itemForPath()`** : factorisation de `itemFromFileInfo()` partagée avec `scanFolder()` → une tuile déposée et une entrée de bureau se résolvent identiquement (nom d'affichage Shell, cible de raccourci, attribut caché).
- **Test** : `appendItemsAddsDedupesAndSorts` (ajout + dédoublonnage + skip vide + tri + sélection vidée + second drop identique = 0).

**Décisions**
- Le chemin Qt et le chemin OLE coexistent volontairement : le premier sert au développement/tests (fenêtre normale), le second est le seul qui fonctionne sur le bureau hébergé. Aucun des deux ne peut être retiré sans casser un mode.
- `OleInitialize` est appelé dans `attach()` et non au démarrage : un init par thread, équilibré par un uninit dans `detach()` (le thread Qt est déjà STA).

**Problèmes rencontrés**
- **Corruption d'un fichier par un edit** : `src/CMakeLists.txt` a été écrasé par le chemin complet du fichier à la place de la liste des sources (edit précédent interrompu). Réparé en relisant puis en réécrivant le bloc. Leçon : après une interruption, **relire** l'état réel de chaque fichier touché avant de continuer.
- **`IUnknown` n'a pas de destructeur virtuel** → `~ShellDropTarget() override` ne compile pas (`marked 'override', but does not override`). Retirer `override`.
- **Includes manquants dans `fence_view.cpp`** : `#include <QMimeData>` (sinon `QDragEnterEvent`/`QDropEvent` ne voient qu'une déclaration anticipée → « invalid use of incomplete type 'const class QMimeData' ») et `#include "platform/win/desktop_scanner.hpp"` pour `itemForPath` (sinon « 'DesktopScanner' has not been declared »).
- **Toolchain** : `export PATH` du bash agent ne propage pas les DLL MinGW/Qt à l'exe ; build + ctest passent avec `dangerouslyDisableSandbox: true` (décision 14 de `STATE.md`, déjà connue).

**Validation**
- Build MinGW 13.1.0 / Qt 6.8.3 : vert.
- `ctest` : **4/4 verts** ; `ui_icon_grid` = **14 cas** (géométrie, sélection, 4 reorder, 1 drop, 2 paint/launch).
- Commit `bbd1cc3` — `feat(ui): accept Explorer drops onto a fence (T-006-3)`.
- Reste la **validation visuelle à l'écran** (T-021) : impossible depuis l'agent (bureau recouvert, décision 13).

**Prochaines actions (voir `STATE.md`)**

## 2026-10-14 — Session 13 : T-007 — cycle de vie des zones

**Objectif** : créer / déplacer / redimensionner / supprimer une zone, avec aimantation (T-007, P0, Phase 3). C'est aussi la pièce qui rendra possible le drag-drop **inter-zones**.

**Décision structurante — séparer la géométrie (pure) du propriétaire des zones**
- `FenceGeometry` ne connaît ni widget ni Win32 → toutes les règles sont unit-testables.
- `FenceContainer` est le **seul** objet qui sait combien de zones existent et où elles sont. Une `FenceView` ne se déplace donc **jamais elle-même** : elle signale un geste, le conteneur décide où il atterrit. C'est ce qui débloque l'inter-zone.

**Fait**
- **`src/ui/fence_geometry.hpp`** (pur, header-only) : `FenceHandle` (None / TitleBar / 8 bords), `hitTest` (6 px de bord, 30 px de barre de titre, **les coins gagnent sur les bords**), `resize` (ouest/nord déplacent l'origine et **épinglent le bord opposé** ; sous la taille minimale on s'arrête au minimum), `snap` (gauche/centre/droite + haut/milieu/bas contre les bords **et** le centre de l'écran **et** de chaque autre zone ; candidat le plus proche, axes indépendants), `clampToBounds` (réduit puis repositionne).
- **`src/ui/fence_container.{hpp,cpp}`** : `FenceWindow` = id + titre + rect + `FenceView` + `DesktopSurface` optionnelle + dernière frame. API `createFence` / `removeFence` / `setFenceRect(id, rect, snap)` / `fenceCount` / `fenceIds` / `fenceRect` / `view` / `surface` / `frame` / `otherRects`. **Mode headless** par défaut (aucun bureau requis) et **mode hébergé** (`setHostOnDesktop(true)`) qui attache une `DesktopSurface` par zone avec le `IDropTarget` OLE câblé comme en T-006-3. `removeFence` supprime la zone, **jamais les fichiers**.
- **`FenceView`** : au clic gauche, `FenceGeometry::hitTest` est évalué **avant** la grille d'icônes → un titre ou un bord démarre un geste de géométrie (`geometryDragStarted` / `geometryDragDelta(handle, delta)` / `geometryDragFinished`). Les deux drags (icône vs zone) sont donc mutuellement exclusifs **par construction**. Curseur reflétant le handle en mode fenêtré.
- **Sonde `starfish --fence-demo [--host] [--seconds N]`** : scénario non interactif, rapport PASS/FAIL dans `build/fence_demo.txt`, code de sortie 0/1.
- **`tests/test_fence_geometry.cpp`** (14 cas) enregistré dans `tests/CMakeLists.txt`.

**Problèmes rencontrés**
- **Le sandbox bloque le lancement de l'exe GUI même avec le bon `PATH`** : `$LASTEXITCODE` vide, aucun fichier écrit, aucune erreur visible (un exe WIN32 ne peut pas signaler un échec de chargement de DLL sur la console). Solution : `Start-Process -Wait` **avec `dangerouslyDisableSandbox: true`**. C'est ce qui a fait croire à tort que la sonde ne produisait rien.
- **Le binaire est en `build/starfish.exe`**, pas `build/src/starfish.exe` (`qt_add_executable` le place à la racine de `build/`) — un premier lancement a échoué pour cette seule raison.
- **`contains()` const appelait `find()` non-const** → ajout d'une surcharge `const FenceWindow* find(...) const`. Erreur remontée par moc, donc dans `mocs_compilation.cpp` : le message pointe le header, pas le `.cpp`.

**Validation**

- `ctest` : **5/5 verts** (0,84 s) ; `ui_fence_geometry` = **14 cas**.
- `--fence-demo` : **8/8 PASS**. Aimantation sur une autre zone : x **394 → 400** (= bord droit de A) ; aimantation aux bords d'écran : **(3,5) → (0,0)** ; clamp de taille : **50×40 → 160×120** ; geste de barre de titre `(-77,+37)` → **(0,120,320,240)** (x aimanté à 0 **et** y aimanté au bas de B) ; poignée bas-droite `+60,+60` → **380×300** ; suppression → count 1.

## 2026-10-14 — Session 14 : T-008 — persistance du layout et restauration

**Objectif** : écrire le layout sur disque et le restaurer au démarrage (T-008, P0, Phase 3). C'est le critère de sortie de la phase : « redémarrage → disposition restaurée à l'identique ; suppression de zone sans perte de fichiers ».

**Décision structurante — séparer le format du document, et différer l'écriture**
- `core::JsonStore` ne connaît que le **format** ; `core::LayoutStore` possède le **document** (chemin, chargement, moment de l'écriture). Même découpage que la géométrie de T-007 : ni widget, ni Win32 → testable sans écran.
- Un drag émet un `fenceRectChanged` **par déplacement de souris** (~60/s). Écrire à chaque signal serait absurde : `LayoutStore` compare le document candidat au document courant (sérialisation déterministe) et n'arme un timer de 500 ms que si les octets diffèrent. Résultat mesuré : rafale de 6 signaux → **1 écriture** ; un clic qui ne change que la sélection → **0 écriture**.
- **Le document, pas le disque, décide de ce qu'une zone affiche** (ADR-7) : une entrée restaurée dont le fichier a disparu est conservée. Une clé USB débranchée ne doit pas vider les zones.

**Fait**
- **`src/core/layout_store.{hpp,cpp}`** : `LayoutStore` (QObject, Qt Core seul) — chemin par défaut `%APPDATA%/StarFish/layout.json` (`QStandardPaths::AppDataLocation`), `load()`, `setLayout()` (retourne `true` seulement si le document change), `scheduleSave()`, `saveNow()`, signaux `layoutLoaded` / `layoutChanged` / `saved` / `saveFailed`. Fichier absent = premier lancement (pas une erreur) ; fichier corrompu ou schéma inconnu = **refusé en conservant le layout courant** ; échec d'écriture → signalé et document laissé sale (retentera au changement suivant).
- **`src/core/jsonstore.{hpp,cpp}`** : `toJson` / `fromJson` extraits de `save` / `load` — c'est ce qui rend la comparaison de documents possible ; `save()` crée le dossier parent (premier lancement sur un profil neuf) ; `itemFromPathOnly()` ajouté à `core/desktop_item` (nom déduit du chemin, drapeaux dossier/caché, **aucun appel Shell**).
- **`FenceContainer`** : `toLayout()` / `applyLayout()` (ids, titres, rects, styles, tri, `rolledUp`, `monitor`, chemins d'items), `setItemResolver()`, `setFenceTitle` / `setFenceStyle` / `setFenceSort`, `fenceItems` / `fenceStyle` / `fenceRolledUp`. `createFence` a été scindé en `addFence` (id demandé ou alloué) pour que `applyLayout` conserve les **ids d'origine** ; le compteur d'ids est avancé au-delà du plus grand numéro restauré. `applyLayout` **remplace** : zones détruites, **jamais les fichiers**.
- **`FenceView`** : `setPanelColor` / `setCornerRadius` / `sortBy` / `sortAscending`. Le remplissage opaque de `renderFence` est **dérivé** de la couleur du panneau → la constante dupliquée `kPanelColor` disparaît.
- **Sonde `starfish --persist-demo [--host] [--seconds N] [--layout FILE]`** : aller-retour par le **câblage produit** (signaux du conteneur → store → écriture différée), puis « redémarrage » (conteneur détruit, nouveau store, `load` + `applyLayout`) et comparaison champ par champ. Rapport `build/persist_demo.txt`, code de sortie 0/1. Option `--layout FILE` ajoutée (chemin du document).
- **Tests** : `tests/test_layout_store.cpp` (9 cas) + 1 cas dans `test_desktop_item.cpp`.

**Corrections de format**
- `FenceStyle::background` par défaut était `#1F2937CC`, c'est-à-dire un RGBA écrit dans l'ordre CSS alors que la convention documentée (et utilisée par le code) est `QColor::name(QColor::HexArgb)` → `#AARRGGBB`. Corrigé en **`#CC1F2937`** ; `docs/technique.md` §5 avait la même erreur (et un `bg` au lieu de `background`, un objet `sort` au lieu de `sort` + `sortAscending`). Le schéma n'ayant encore rien écrit sur disque, la correction est gratuite.

**Problèmes rencontrés**
- **Premier jet de sonde en échec (1/27)** : « the change signals auto-saved » attendait une écriture **sans laisser le timer tirer** — six changements synchrones, puis `saveNow()` qui annule le timer. Ce n'était pas un bug du code mais une attente fausse : le test a été retourné en « la rafale entière produit **exactement une** écriture », ce qui est une vérification plus forte (et c'est elle qui a validé le debounce).
- Le tool PowerShell ne remonte pas le stdout des commandes : passer par un fichier (`Out-File`) puis lire le fichier. Le build lui-même était déjà vert (« ninja: no work to do » au second appel).

Mesuré : rafale de 6 signaux → **1 écriture** ; sélection qui change → **0 écriture** ; rect aimanté **440,400 280x200** retrouvé à l'identique après redémarrage ; document **identique octet pour octet** après aller-retour ; zone supprimée absente du fichier ; corrompu refusé (`unterminated object`) avec le layout conservé ; fichier absent = premier lancement.
