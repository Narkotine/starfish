## 2026-10-14 — Session 12 : T-006 pièce 3 — DnD `CF_HDROP` depuis l'Explorer

**Objectif** : accepter le drop de fichiers/dossiers depuis l'Explorer Windows vers une zone (T-006-3), en réutilisant la résolution d'items du scan bureau. La session a été interrompue une fois par la limite de fréquence (429) puis reprise.

**Fait**
- **Deux chemins, parce que la zone vit à deux endroits** :
  1. **Fenêtre Qt réelle** — `FenceView::setAcceptDrops(true)` + `dragEnterEvent`/`dragMoveEvent`/`dropEvent`. Qt expose le `CF_HDROP` de l'Explorer comme une liste d'URLs `file://` (`mimeData()->hasUrls()`). Chaque chemin local est résolu par `DesktopScanner::itemForPath()`, puis `addDroppedItems()`.
  2. **Surface hébergée** — Qt ne tourne jamais (la zone est une image hors écran, seul le HWND Win32 est à l'écran) : `DesktopSurface` enregistre un `IDropTarget` OLE (`ShellDropTarget`) sur son propre HWND. `CF_HDROP` → `DragQueryFileW` → handler `(point client, chemins)`. `OleInitialize` dans `attach()` (équilibré par `OleUninitialize` dans `detach()`), `RegisterDragDrop`/`RevokeDragDrop`, `setDropHandler`. `main.cpp` câble le handler à `fence->addDroppedItems`.
- **`ShellDropTarget`** (`src/platform/win/shell_drop_target.{hpp,cpp}`) : `IDropTarget` COM, comptage de références `InterlockedIncrement/Decrement`, `QueryGetData`/`GetData(CF_HDROP)` + `DragQueryFileW`. Le point de drop arrive en coordonnées écran → converti en coordonnées client via `GetWindowRect`.
- **`IconGrid::appendItems()`** : dédoublonnage par chemin, skip des items sans chemin, re-tri selon l'ordre courant, sélection vidée (un drop est un lot neuf). Retourne le nombre d'items ajoutés.
- **`DesktopScanner::itemForPath()`** : factorisation de `itemFromFileInfo()` partagée avec `scanFolder()` → une tuile déposée et une entrée de bureau se résolvent identiquement (nom d'affichage Shell, cible de raccourci, attribut caché).
- **Test** : `appendItemsAddsDedupesAndSorts` (ajout + dédoublonnage + skip vide + tri + sélection vidée + second drop identique = 0).

**Décisions**
- Le chemin Qt et le chemin OLE coexistent volontairement : le premier sert au développement/tests (fenêtre normale), le second est le seul qui fonctionne sur le bureau hébergé. Aucun des deux ne peut être retiré sans casser un mode.
- `OleInitialize` est appelé dans `attach()` et non au démarrage : un init par thread, équilibré par un uninit dans `detach()` (le thread Qt est déjà STA).

**Problèmes rencontrés**
- **Corruption d'un fichier par un edit** : `src/CMakeLists.txt` a été écrasé par le chemin complet du fichier à la place de la liste des sources (edit précédent interrompu). Réparé en relisant puis en réécrivant le bloc. Leçon : après une interruption, **relire** l'état réel de chaque fichier touché avant de continuer.
- **`IUnknown` n'a pas de destructeur virtuel** → `~ShellDropTarget() override` ne compile pas (`marked 'override', but does not override`). Retirer `override`.
- **Includes manquants dans `fence_view.cpp`** : `#include <QMimeData>` (sinon `QDragEnterEvent`/`QDropEvent` ne voient qu'une déclaration anticipée → « invalid use of incomplete type 'const class QMimeData' ») et `#include "platform/win/desktop_scanner.hpp"` pour `itemForPath` (sinon « 'DesktopScanner' has not been declared »).
- **Toolchain** : `export PATH` du bash agent ne propage pas les DLL MinGW/Qt à l'exe ; build + ctest passent avec `dangerouslyDisableSandbox: true` (décision 14 de `STATE.md`, déjà connue).
